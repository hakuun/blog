---
title: AI 让答案更近，也让一些东西更远
description: Agent 正在缩短从目标到结果的距离。速度之外，搜索、试错和偶然发现留下了什么？
pubDate: 2026-07-18
---

最近读到《纽约时报》的一篇文章，标题很长，意思却很直接：我们正在失去发现“自己原本不知道该问什么”的能力。

文章从一个数字写起。美国超过六成的 Google 搜索，现在不会带来链接点击。人们输入问题，在搜索页顶部读完 AI 生成的摘要，然后离开。搜索引擎、ChatGPT、Claude、Perplexity 这类产品，都在做相似的事情：接住一个问题，尽快给出一个像样的答案。

这很符合直觉。过去的搜索体验里，有太多需要跳过的内容：广告、重复页面、标题党、为了一个结论打开十几个标签页。很多时候，搜索本身比问题更让人疲惫。摘要把这些步骤压缩掉，省下来的时间是真实的。

作者关心的是另一部分体验。

搜索曾经有一段不太受控制的过程。点开一篇文章，发现它只讲了一半，于是顺着引用继续读；看到一个陌生的概念，顺手再搜几下；本来在找 A，最后却在 B 或 C 上停留更久。最初的问题也许解决了，也许没有完全解决。脑子里却多了一条线索，或者多了一个以后会在别处用上的问题。

这类过程看起来很散，也不总能带来有用的结果。可很多学习和发现，本来就没有一个清晰的任务名。它们发生在路上：多看了一页，多点了一个链接，多花了几分钟在当下无关紧要的内容上。

文章引用了一些关于好奇心的研究。人在等待一个感兴趣问题的答案时，记忆系统会处在更活跃的状态，对周围信息的吸收也会更好。好奇心像是打开了一扇窗。答案来得太快，窗也会很快关上。

读到这里时，我想到的不是搜索，而是最近发展很快的 Agent。

## 从问题到答案，从目标到结果

搜索摘要缩短了从问题到答案的距离。Agent 进一步缩短了从目标到结果的距离。

以前遇到一项陌生任务，人通常会自己完成一串步骤：理解需求，找资料，读文档，问同事，拆分任务，试几个方向，开始执行，再根据结果调整。过程里有很多重复劳动，也有很多细碎的判断。

现在，Agent 可以接过其中一段，甚至接过整段流程。

让它调研一个领域，它可以先找资料、提炼观点、列出来源；让它处理一个代码任务，它可以读仓库、理解相关文件、写计划、修改代码、执行测试；让它整理一份材料，它可以提取信息、归类、生成初稿，再按反馈修改。每一个环节都还会犯错，每一种工具也都有明显边界。但任务从“完全空白”到“有一个可审阅的第一版”，已经快了很多。

这种速度变化会继续发生。模型能力在提升，工具调用和代码执行在变成熟，越来越多原先需要人手动衔接的步骤被放进同一条工作流。个人很难决定这股变化的方向，也很难假装它与自己无关。

学习使用 Agent，大概会慢慢成为一种日常能力。它和熟练搜索、写文档、使用表格软件没有本质上的神秘感。工具会进入工作，就像其他工具曾经进入工作一样。

变化在于，工具承担的部分变多了，人站的位置也跟着往前移。

## 人开始更早地面对任务

使用 Agent 时，最先出现的问题往往不是“它会不会做”，而是“我到底希望它做什么”。

一个任务交出去之前，需要交代目标、背景、已有材料、限制条件和完成标准。只说“帮我调研一下”“优化一下这个功能”“写一个方案”，通常只能得到一份看起来完整的内容。标题、结构、措辞都可能不错，真正落到业务和具体场景时，常常会发现它理解的是另一个问题。

Agent 并不了解那些没有写下来的部分。

它不知道团队过去为什么做过某个取舍，不知道一个字段背后藏着哪些兼容性问题，也不知道用户一句模糊的抱怨，究竟指向体验、流程还是预期。它可以根据现有信息做合理推断，却无法天然拥有现场感。

于是，人的工作会更多地出现在任务开始之前，也会贯穿任务进行的过程。

开始之前，要把问题想清楚。这里的“想清楚”并不等于写一篇很长的提示词。更重要的是分清目标和手段，知道哪些事情可以交给工具探索，哪些地方必须保留约束，什么结果可以接受，什么结果即使能跑也不能用。

任务进行时，要看 Agent 的计划是否漏了关键环节，搜索范围是否太窄，依据是否可靠，执行有没有偏离目标。它给出一个结论后，还要判断结论和现实之间是否存在断层。

这听起来像是多了一层工作，实际体验却不完全如此。许多具体操作被接过去以后，人有机会把注意力放到更靠前的地方：问题是不是定义对了，方向是不是值得继续，结果有没有碰到真正要解决的部分。

Agent 的能力越强，这些判断的重要性越高。工具可以把路径走得很快，路径通向哪里，仍然需要人来决定。

## 被压缩的中间过程

这里很容易产生一种矛盾的感受。

一方面，大家当然希望工作更快。整理资料、复制内容、跑固定流程、做机械比对，这些事情消耗时间，也很少带来成就感。Agent 能把它们处理掉，很多任务会变得轻松一些。

另一方面，过去那些看起来笨拙的过程里，确实混着一些难以替代的东西。

自己查资料时，往往会碰到没有放进最终报告的内容。自己读代码时，常常会顺手看到相邻模块的写法。自己试一个方案时，也会更直观地感受到哪里别扭、哪里缺信息、哪里和预期不同。这些感受未必能直接转成结论，却会慢慢影响之后的判断。

Agent 会把大量中间内容折叠起来。它筛选资料，读完后输出摘要；它分析代码，最后给出修改建议；它跑完一串操作，将可交付的结果放在面前。人得到的是整理后的版本，也是工具认为最相关的版本。

大部分时候，这正是我们想要的。

可在筛选和折叠的过程中，有些旁支也会消失。没有被选进报告的资料，没有被点开的页面，没有被保留下来的异常现象，以及没有来得及冒出来的疑问。它们大多数没有价值，甚至可以说，正因为大量内容没有价值，效率工具才显得必要。

偶然发现的困难也在这里。它没有办法提前指定哪些内容值得偶遇。一个看似无关的案例，可能在很久以后帮助理解另一个问题；一次没有继续追查的异常，可能正好是值得深入的方向。把所有噪声都消掉，偶然性也会一起变少。

NYTimes 那篇文章担心的，就是这种变化的长期积累。人会越来越熟练地提取现成结论，却可能更少在不确定的信息里建立自己的连接。

这个担心放到 Agent 上，同样值得想一想。

## 更快的工作，和更快的结论

Agent 会让很多事情加速。一个任务可以更快开始，方案可以更快成形，代码可以更快出现，文档可以更快流转。组织里的任务链条也可能因此变得更密。

这会带来实际的好处。很多人不再被零碎、重复的工作困住，可以把时间用在更复杂的事情上。小团队可以尝试过去需要更多人手才能尝试的方向，个人也能进入原本门槛很高的领域。

同时，速度本身会改变工作环境。

当第一版方案只需要几分钟，等待完整思考的耐心会变少；当资料很容易被汇总，花时间读原始材料会显得奢侈；当结论总能迅速生成，追问结论从哪里来、遗漏了什么，也会显得有些多余。

这些变化不一定会以明确的规则出现。它们更像一种新的默认值。任务来了，先让 Agent 跑一遍；有了结果，快速选一个方向；下一项任务已经在等着。流程会很顺，产出也会更多。

真正麻烦的问题通常不长在这样的流程里。

用户为什么在某个环节离开？一个看似合理的需求为什么落地后没有效果？两条彼此无关的反馈，会不会指向同一件事？某个指标的变化，到底来自产品本身，还是来自环境变化？

这类问题没有标准输入，也很少在第一轮任务里出现。它们需要人在日常工作中看到一些不完全符合预期的细节，然后愿意停留一下。Agent 能帮助扩大搜索范围，整理线索，验证猜测；它也能让人更快试出一个答案。至于什么值得继续追，往往还是要靠人的经验、直觉和对具体情境的在意。

## 让工具替我们跑，也看一看路

这篇文章并不导向一个简单的结论。放慢速度并不天然更好，手动完成一切也没有必要。面对明确且重复的任务，用 Agent 把过程压缩掉，是很自然的选择。

真正值得讨论的，或许是人和工具之间会形成怎样的关系。

有人把 Agent 当作一个执行者：任务交出去，等待结果，再进行验收。有人把它当作一个可以共同推演的对象：让它先提出计划，自己补充背景和约束，在过程中不断修改问题，再一起接近一个更好的结果。两种方式都会提高效率，后者可能更接近 Agent 真正适合的位置。

它很擅长展开、列举、比较、执行和反复尝试。人可以把它推向更远的地方，也需要在关键处拉住它。提出一个好问题，设计一个能被检验的任务，看到它走偏后重新调整，这些事情不会随着工具变强而消失。

也许未来更稀缺的东西，不是答案，也不是生成答案的能力。信息会越来越便宜，执行也会越来越容易。对一件暂时没有结论的事保持兴趣，发现问题的轮廓，愿意再往下挖一层，这些能力可能会越来越重要。

AI 的发展还会继续加速。学习使用 Agent，理解它的边界，参与这股变化，大概会成为很多人的选择。

与此同时，或许也可以给一些没有立刻产出的过程留一点位置。偶尔读一读原文，偶尔看看报告之外的资料，偶尔在一个“好像哪里不对”的感觉上多停几分钟。

这些绕路未必会带来答案。它们有时会带来下一个问题。

而下一个问题，可能比一个很快得到的答案更值得留下。
